# 美术实装提交流程

固定复用 `li/art-integration`，由 Li 更新分支并创建或追加 PR，班审查后合并到 `main`。合并后保留固定分支，后续继续使用，不再按日期新建分支。

## 资源和 GUID

- 班提供 PNG、Aseprite 等原稿；Li 在 Unity 中完成导入、切片、轴心、每单位像素数、动画绑定和 Prefab 实装。
- Unity 生成的 `.meta` 保存资源 GUID 和导入配置；PNG 的切片还包含精灵子资源的标识与映射。对应目录的 `.meta` 也需要提交。
- 同一次实装中，将相关新建或修改的 `.meta` 与资源、Prefab、动画、脚本和测试一起提交。原图已经在 GitHub 且没有改动时，Git 会复用原图，只提交新增的导入信息和实装差异。
- 后续更新保留已有 `.meta`；移动或重命名资源时一起移动 `.meta`。重复切片复用已有精灵 ID，避免破坏场景与 Prefab 引用。

## 发布步骤

1. 获取最新主线与固定分支，核对上次 PR 的状态。上一条已合并时，快进或正常合并 `origin/main`，保留已发布历史。
2. 检查本次资源与 `.meta` 是否配套、GUID 是否重复、Prefab 引用是否有效，并按改动范围验证导入与运行表现。
3. 更新 `Docs/CHANGELOG.md`，仅暂存本批美术实装相关文件，提交后推送固定分支。
4. 有未合并 PR 时更新同一 PR；没有时从固定分支向 `main` 创建正式 PR，写明素材、导入参数、实装范围和实际验证结果。
5. 班审查后决定合并或关闭；固定分支保留。会议记录继续使用会议专用分支，Unity 缓存和 IDE 临时改动按仓库规则处理。

Issue 操作仍遵循 `AGENTS.md` 的明确授权要求。
