# 会议记录提交流程

会议记录固定复用 `li/docs-meetings`。流程为更新分支、创建或更新 PR、由班审查并合并到 `main`。合并后保留该分支，下一次继续使用。

## 操作步骤

1. 读取原项目的会议文件，检查 DOCX 完整性；原文件保留在原项目中。
2. 复用独立的会议工作目录处理提交，保持 Unity 工程的当前分支和未提交改动。固定分支用于会议文件与对应说明，其他开发改动按各自任务处理。
3. 获取最新远端状态。若固定分支有未合并 PR，向该分支追加本次更新，并更新同一个 PR 的说明。
4. 若上一条 PR 已合并，先把最新 `origin/main` 同步进固定分支：能快进则快进，否则正常合并主线并解决相关冲突。保留已发布历史，避免 reset 或强制推送。
5. 将本次会议文件复制到 `Docs/会议记录/`，更新 `Docs/CHANGELOG.md`，仅暂存本次会议相关文件，检查差异后提交并推送。
6. 没有未合并 PR 时，从 `li/docs-meetings` 向 `main` 创建正式 PR，写明本次会议日期、改动和文件检查结果。
7. 班审查后决定合并或关闭。固定会议分支保留；后续会议继续重复以上流程。

如果固定分支被误删，在最新主线上恢复同名分支，不再创建新的日期分支。Issue 操作仍遵循 `AGENTS.md` 的明确授权规则。
